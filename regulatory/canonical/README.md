# Canonical regulatory requirements (initial increment)

Run `python src/canonical_requirements.py /path/to/new-output` to build canonical JSON, JSONL, SQLite FTS5 and section coverage/migration from the committed registry and pinned source records. SQLite is generated, not a second maintained rule copy. Python standard library only; SQLite must include FTS5. Use `search(path, query)` for local retrieval. Historical annex/N IDs resolve through migration; empty targets mean unresolved, not deleted. Never reuse a semantic ID for a different obligation; amendments change the rule-version hash. Do not convert candidate wording to executable criteria without independent verification and reviewed product-evidence logic.

This is a deliberately partial canonical registry. The legacy inventory remains immutable evidence. CLP and REF11 entries remain reference-only; ECHA playbooks retained separately. All 17 sections remain incomplete; manual findings and coverage gaps prevent any claim of comprehensive compliance. Nine evaluator categories are represented by a manual dispatcher only; deterministic rule implementation is a separate gate. The existing engine is not replaced. See SOURCE_VERIFICATION.md for source checks and unresolved dependencies.

Pass `--sources /path/to/original-pdfs` to verify all five hashes and add raw layout-preserving PDF pages to FTS5. Printed pages remain unset for unreviewed extractions. The legacy Gemini generator also bundles the registry. New exchanges include a hash of assessed rule versions in the sources header; old exchanges retain their format.

`retrieve_clause(path, clause)` provides exact clause lookup; source record clauses retain legacy syntax (e.g. `1.1`), canonical clauses include `Annex II Part A`. `resolve_legacy(pack, legacy_id)` returns the historical disposition. `coverage_matrix.json` is a generated snapshot, not an independent rule source.
