# SDS Phrase Selection Engine

An offline, English-language SDS phrase authoring assistant using the **eSDScom 5.5** phrase catalogue. Python 3.10+ standard library only.

**WARNING:** This v0.1 is a draft authoring tool, not a validated SDS generator. Its seven illustrative rules do not implement all CLP Annex IV, EU/GB REACH Annex II or OSHA HazCom 2024 requirements. Human review is required before phrases appear in a finished SDS. Zero matches never establish regulatory compliance.

## How to run on Ubuntu

Clone the feature branch:

    git clone -b feature/rule-based-phrase-engine-v1 https://github.com/ConorTttttt/SDS-Phrases.git
    cd SDS-Phrases

Use your original eSDScom 5.5 source ZIP containing both Core and Exposure Scenario workbooks (the uploaded file was named eSDScom_V5-5_20231131.zip). Import it locally:

    python3 src/import_catalogue.py ~/Downloads/eSDScom_V5-5_20231131.zip

The importer writes **data/catalogue.sqlite**. Alternatively, if you already downloaded the previously generated **esdscom55_english.sqlite**, copy that existing file to **data/catalogue.sqlite** instead. It is compatible with the engine.

Start the server:

    python3 src/server.py

Open **http://127.0.0.1:8092/**. Stop with Ctrl+C. To reach it from a phone on trusted home Wi-Fi, start with:

    python3 src/server.py --host 0.0.0.0

Then visit http://YOUR_DESKTOP_PRIVATE_IP:8092/ on the phone. There is **no authentication**: do not expose the server to the internet or untrusted networks.

## Included capabilities

- Browse/search original English catalogue entries across 16 SDS sections, filtered by wording, original H/P code, structure code, collection or EU/GB/US SDS structure.
- Enter independently classified H-statements; confirm specific formulation facts.
- Select candidate wording only when jurisdiction, hazard conditions, evidence conditions, section, exact structure code and exact expected source English wording match.
- Inspect original wording, catalogue identifiers, internal source key, rule rationale, matched hazards, evidence checks and draft status.
- View missing evidence and blocked rule matches rather than silent wording substitutions.
- Use three jurisdiction modes: EU, GB and US. Most pilot rules apply only to EU/GB; one glove-guidance rule supports US. This is not yet a complete legal rule set for any jurisdiction.

## Layers

1. **Catalogue** — original user-provided eSDScom 5.5 Core and Exposure Scenario workbooks; stored locally only.
2. **Importer** — src/import_catalogue.py; preserves source fields and indexes jurisdiction structures and SDS sections. Source Excel cells are never rewritten.
3. **Rules** — rules/pilot-eu-gb-v1.json; seven draft conditions with expected exact catalogue wording and evidence gates.
4. **Evaluator** — src/engine.py; fails closed where exact source matches are absent or changed.
5. **Interface** — src/server.py and web/*; no external libraries.

Core workbook official phrase IDs are blank in the supplied source. The internal row key and structure code are **not official phrase IDs**. The source filename includes the invalid date 20231131; the filename is preserved, not treated as the regulation's effective date.

The phrase database is excluded from GitHub due to upstream licence terms and to avoid redistributing an adapted catalogue. Verify current eSDScom licence terms before redistributing phrase-derived data.

- GET /api/info — installed catalogue and draft ruleset metadata
- GET /api/rules — rule definitions
- GET /api/search — phrase catalogue search (query, jurisdiction, section, collection, limit)
- POST /api/evaluate — JSON with jurisdiction, hazards array, verified facts boolean object, optional sections array

Example request:

Expand the formulation data model for exposure routes, physicochemical properties, use, protective equipment, waste and transport. ## Phase 1: catalogue-quality browser (feature branch)

The original source catalogue is indexed **locally** without changing the source text. The new browser provides:

- SDS section and derived subsection/category filters; section paths are **browsing aids, not regulatory applicability proof**.
- Search by English wording, original code, structure code and populated official phrase IDs; paginated results.
- Original workbook name, Excel row, structure, provenance, phrase owner, grammar, revision metadata and source notes.
- Normalised-wording duplicate groups **without deleting repeated source entries**.
- Indicators for special structures (including Core 11/12/14 and Exposure Scenario 09), blank English wording, unrecognised subsection paths and possible template parameters.
- A separate local metadata-review note database at data/catalogue_reviews.sqlite, retained when the catalogue is reimported. Statuses are *unreviewed*, *metadata checked* and *needs attention*. **None means regulatory approval.**
- A source ZIP SHA-256 digest recorded on import. Source workbook revision dates are **not regulatory effective dates**.

Use your existing checkout under /mnt/holochain/Regulatory/SDS_Phrases:

    cd /mnt/holochain/Regulatory/SDS_Phrases
    git fetch origin
    git switch --track origin/feature/phase1-catalogue-quality-browser

If the catalogue was already imported using v0.1, upgrade the database in place:

    python3 src/catalogue_index.py data/catalogue.sqlite

For a new import, the importer automatically builds the index:

    python3 src/import_catalogue.py ~/Downloads/eSDScom_V5-5_20231131.zip

Start the local service:

    python3 src/server.py

Open http://127.0.0.1:8092/catalogue.html for the new catalogue-quality browser; the draft rule engine remains at http://127.0.0.1:8092/.

**Security:** Review writes are allowed only when the server is bound to local loopback (the default). A server started with --host 0.0.0.0 is not authenticated and intentionally rejects review writes; avoid publishing it on untrusted networks.

**Limitations:** Quality indicators are not necessarily errors. A normalised duplicate group is not an assertion that two source rows have equivalent regulatory meaning. Section 16 has no fixed subsection mapping. All derived subsection labels must be checked by an SDS expert. No legal selection rules are introduced in this phase.

After checking out the branch:

    cd /mnt/holochain/Regulatory/SDS_Phrases
    git fetch origin
    git switch --track origin/feature/phase2-regulatory-engine-foundation
    python3 -m unittest discover -s tests -v
    python3 src/server.py

Open **http://127.0.0.1:8092/regulatory.html**. Use “Load fictional test inputs”
to explore H315/H319 data-completeness prompts and the full decision trace.

**This is not yet a CLP/REACH/HazCom/WHMIS legal rule set.**
No legal requirement has been verified as part of Stage A. The demonstration
cannot label a phrase mandatory, supply legally prescribed wording, or
declare any SDS section compliant. Every outcome contains the source
identity, version, date scope, evidence and missing facts. Missing data
is unknown, never an assumed negative.

The local service also offers \`GET /api/regulatory/pack\` and
\`POST /api/regulatory/evaluate\`; no original eSDScom database is required
for these new endpoints. See [Stage A technical documentation](docs/regulatory_engine_stage_a.md)
for the input schema, tri-valued rule conditions, legal review gates, test
coverage and subsequent regulatory validation requirements.

**Next:** Import independently reviewed EU CLP Annex IV Part 1 selection rules
and Part 2 English wording with regulation citations and amendment/effective
dates, then model EU REACH Annex II SDS information requirements separately.
Do not infer mandatory phrases from catalogue membership.

## Phrase recommendations for all 16 SDS sections (draft pilot)

The \`feature/phase2-section-phrase-recommendations\` branch adds a new
**section-by-section recommendation workspace** with 21 curated, documented
authoring conditions across all 16 EU SDS sections. The original 52,676 English
source entries remain local and unmodified; the Git repository stores
original phrase structure codes and exact wording SHA-256 fingerprints, not
source catalogue wording.

Set product type, H statements, classification evidence and section-specific
facts. The new engine explains: matching **draft candidates**, absent evidence,
non-triggering conditions, and source/version mismatches. Every section is
displayed, including where no eligible text exists. No output is legally
mandatory or approved.

\`\`\`bash
cd /mnt/holochain/Regulatory/SDS_Phrases
git fetch origin
git switch --track origin/feature/phase2-section-phrase-recommendations
# Import original phrase ZIP once, if data/catalogue.sqlite is missing:
python3 src/import_catalogue.py ~/Downloads/eSDScom_V5-5_20231131.zip
python3 scripts/verify_section_phrase_sources.py
python3 -m unittest discover -s tests -v
python3 src/server.py --port 8093
\`\`\`

Open **http://127.0.0.1:8093/section_recommendations.html**.
See [technical design and regulatory limitations](docs/section_phrase_recommendations.md).

**Important:** This release is a supported drafting workflow, not a
legally verified SDS compliance generator. REACH Annex II determines
information requirements, CLP Annex IV determines P-statement selection,
and eSDScom provides optional phrase candidates. Those layers are still
separate and their detailed crosswalk awaits independent verification.
